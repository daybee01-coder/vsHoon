# VSsh 고도화 작업 기록

## 구현 범위

- VSsh의 기본 설정에서 `window.restoreWindows`를 `none`으로, 터미널 영속 세션을 비활성화하고 종료 확인을
  `never`로 지정했다. 사용자가 명시적으로 설정한 값은 VS Code의 설정 우선순위에 따라 이 기본값보다 우선한다.
- 기본값만으로는 기존 사용자 설정을 이길 수 없으므로 VSsh가 생성하는 SSH·WSL 터미널 양쪽에
  `isTransient: true`를 직접 지정했다. 따라서 사용자가 터미널 영속 세션을 켜 두어도 VSsh 터미널은 창을
  닫거나 다시 시작한 뒤 복원되지 않는다.
- `vssh.connected` 컨텍스트가 참일 때만 SFTP 웹뷰를 노출한다. 연결 시 기존처럼 SFTP 패널에 포커스를 주고,
  마지막 연결이 닫히면 뷰가 숨겨진다.
- 원격 파일은 `os.tmpdir()/vshoon-vssh-edits/edit-*` 아래의 고유 디렉터리에 내려받은 뒤 연다. 원격 파일명을
  Windows에서 안전한 로컬 파일명으로 정규화하며, 원본은 SHA-256으로 식별한다.
- 텍스트 파일은 vs Hoon 편집기로 연다. 마지막 탭이 닫힌 뒤 임시 파일의 실제 내용이 바뀐 경우에만
  `업로드`, `변경 버리기`, `다시 열기`를 묻는다. 편집기 그룹 사이의 탭 이동은 닫기로 취급하지 않는다.
- 업로드 전에 원격 파일의 크기와 수정 시각을 다시 확인한다. 서버에서도 파일이 변경된 경우 별도 덮어쓰기
  확인을 요구하고, 업로드는 같은 원격 디렉터리의 임시 파일과 백업 파일을 이용해 교체한다.
- 바이너리 파일은 vs Hoon 기본 뷰어, 운영체제 기본 앱, Windows의 다른 앱 선택 창 중에서 고른다.
  외부 앱을 사용한 경우 사용자가 편집 완료를 알린 뒤 동일한 변경 확인·업로드 흐름을 수행한다.
- 로컬 패널 도구 모음에 현재 디렉터리를 운영체제 파일 탐색기로 여는 동작을 추가했다.
- SSH 터미널은 로그인 셸이 bash, zsh, fish인 경우 프롬프트 훅이 화면에 보이지 않는 VShoon 경로 신호를
  내보내게 한다. WSL 터미널도 같은 셸들을 대상으로 사용자 셸 설정을 읽은 뒤 VS Code 표준 CWD 신호를
  내보내며, shell integration의 경로 변경 이벤트를 통해 같은 흐름에 연결한다. 활성 터미널의 경로 신호만
  SFTP 원격 패널에 반영하며, 오래 걸린 이전 조회가 수동 탐색이나 새 세션을 덮어쓰지 못하게 요청 세대를
  검사한다. `vssh.sftp.autoFollowTerminal`은 기본적으로 켜져 있고 SFTP 타이틀 명령으로 전환할 수 있다.
  지원하지 않는 셸에서는 기존 **터미널 위치로 이동** 명령을 fallback으로 유지한다.
- 사용이 끝난 변경 없는 임시 파일은 즉시 삭제한다. 사용자가 보존한 파일과 실패한 업로드 파일은 경로를
  안내하며, 7일 이상 지난 VSsh 편집 임시 디렉터리는 다음 활성화 때 정리한다.

## 검증

- `npm run test:vssh`
  - VSsh 확장 TypeScript 컴파일: 오류 0
  - 단위 테스트: 15개 통과
  - 추가 검증: 텍스트/바이너리 판별, Windows 임시 파일명 정규화, 원격 파일 충돌 판정
- 추가된 원격 편집 파일 3개 대상 ESLint: 오류·경고 0
- SSH 셸 경로 추적 단위 테스트 5개 통과: 셸 판별, 프롬프트 훅 생성, 분할 OSC 처리, 경로 검증,
  비정상 신호 버퍼 상한
- WSL 셸 경로 추적 단위 테스트 2개 통과 및 실제 WSL `sh -n`, `bash -n` 문법 검사 통과
- `npm run sync:check`: overlay 542개 일치. 네트워크 차단으로 upstream 원격 표류 조회만 건너뜀.

VSsh 전체 소스 ESLint는 기존 코드의 헤더 및 중괄호 규칙 위반 221건(오류 36, 경고 185) 때문에 실패했다.
이번에 추가한 파일은 별도 범위 검사로 통과했으며, 기존 파일의 광범위한 자동 수정은 이 작업 범위에 포함하지 않았다.

패키징과 실제 서버 연결을 이용한 수동 확인은 이 작업에서 실행하지 않았다.
