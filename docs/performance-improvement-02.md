## 변경 내용

### 1. 목록 수명을 별도 단위로 분리

새 [fileDialogListing.ts](../src/vs/vshoon/common/fileDialogListing.ts)가 디렉터리 읽기의 수명을 소유한다. `common` 계층이며 DOM·`IFileService`를 참조하지 않고 읽기 함수를 주입받으므로, 느린 디렉터리를 단위 테스트에서 그대로 재현할 수 있다.

- `list(uri)`는 새 세대를 시작한다. 진행 중이던 요청은 모두 `stale`로 끝난다.
- `listWithin(uri, generation)`은 이미 표시된 목록 안의 읽기(행 확장)다. 세대가 바뀌었으면 읽기를 시작하지도 않는다.
- `cancel()`은 대화상자가 닫힐 때 남은 결과를 버린다.
- 필터와 정렬(디렉터리 우선, 이름순)은 기존 `passesFilter`/`sort`의 동작을 그대로 옮겼다.

파일 시스템 읽기 자체를 중단하지는 못한다. 늦게 도착한 결과를 화면에 적용하지 않을 뿐이다.

### 2. 조기 표시

[vshoonFileDialog.ts](../src/vs/vshoon/browser/fileDialog/vshoonFileDialog.ts)의 `show`는 `await render()` 뒤에 `widget.show()`를 호출했다. 시작 폴더 확인(`stat`)과 첫 목록 읽기가 끝날 때까지 화면에 아무것도 없었다.

현재는 종료·취소 처리기를 먼저 등록하고 위젯을 표시한 뒤, 시작 폴더 확인과 목록 읽기를 진행한다. 그 사이 상태 줄은 "Loading…"이고 취소·닫기가 동작한다. 저장 대화상자의 시작 폴더는 I/O 없이 정해지므로 표시 전에 확정해, 잘못된 경로가 잠깐 보이지 않게 했다.

### 3. 행 리스너 수명

`createRow`의 클릭·더블클릭 리스너는 대화상자 전체 `store`에 등록되어 폴더를 옮겨도 대화상자가 닫힐 때까지 남았다. 현재는 렌더 단위 `DisposableStore`에 등록하고 매 렌더 시작에서 `clear()`한다. 새 폴더 편집기도 `MutableDisposable`이 소유해, 버튼을 반복해서 눌러도 이전 편집기의 리스너가 쌓이지 않는다.

| 상황 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 위젯 표시 시점 | 첫 목록 렌더 완료 후 | 시작 폴더 확인 전 |
| 폴더 N회 이동 후 살아 있는 행 리스너 | 지금까지 만든 모든 행 | 현재 폴더의 행 |
| 느린 폴더 → 다른 폴더 이동 시 늦게 온 결과 | 새 목록에 덧붙음 | `stale`로 버림 |
| 새 폴더 편집기 N회 열기 | 리스너 N개 | 리스너 1개 |

이는 코드 경로와 단위 테스트로 확인한 동작 차이이며, 시간·메모리 실측값이 아니다.

유지한 동작: 히스토리 앞뒤/홈/상위/새로고침, 필터·정렬 규칙, 행 확장·접기, 더블클릭 열기, 경로 입력 Enter, Escape 취소, `role`/`aria-*` 속성과 초기 초점, 실패 폴더의 오류 메시지와 빈 폴더 안내. `VShoonFileDialog`의 공개 API는 그대로이므로 [VSH-0011 seam 패치](upstream-patches.md)는 변경하지 않았다.

## 검증

- `npm run typecheck`: 통과.
- `npm run lint`: 통과(오류·경고 0).
- `npm test`: 52개 통과, 실패·건너뜀 0. 이 중 새 [fileDialogListing.test.ts](../src/vs/vshoon/test/common/fileDialogListing.test.ts)의 7개는 정렬·필터, 느린 폴더가 다음 폴더를 덮지 않음, 늦게 도착한 실패를 오류로 표시하지 않음, 현재 폴더의 실패 메시지, 행 확장의 세대 판정, 닫힘 시 취소를 확인한다. 느린 응답은 테스트가 직접 완료 시점을 제어하는 reader로 재현했다.
- `npm run valid-layers-check`: 위반 6건. 모두 변경 전과 동일한 `INativeEnvironmentService`의 browser 계층 참조이며, 변경 전 파일로 되돌려 같은 수를 확인했다. 이번 변경으로 늘어난 위반은 없다. 기존 위반의 해소는 별도 과제로 남긴다.
- `npm run sync:check`: 통과.
- 실행 검증은 하지 않았다. 이 대화상자를 다루는 smoke 스크립트가 없고 빌드·데스크톱 실행을 수행하지 않았으므로, **실제 창에서의 첫 표시 시점, 키보드·스크린 리더 흐름, 원격 provider 동작은 미확인**이다.
- 첫 표시 지연, 목록 준비 시간, 반복 이동 후 메모리 추세의 수치 비교도 하지 않았다.
