# Decom - JAR/Class 디컴파일러

JAR/class 파일을 디컴파일하여 VSCode에서 열람하고, JAR 안의 리소스(xml/properties/txt 등)나
내장 라이브러리(jar) 등을 직접 수정한 뒤 원본 JAR에 다시 저장할 수 있게 해주는 확장입니다.
`.class`는 항상 읽기 전용으로만 열람합니다(수정 대상 아님).

## 요구사항

- JDK가 설치되어 있고 `java` 명령을 사용할 수 있어야 합니다(CFR 실행용). 경로가 다르면
  `decom.java.executable` 설정으로 지정하세요.
- 디컴파일러는 [CFR](https://github.com/leibnitz27/cfr)을 사용하며, 최초 사용 시 GitHub
  릴리스에서 자동으로 내려받아 sha256 무결성을 검증한 뒤 확장 저장소에 캐시합니다.
  (오프라인 환경이라면 `decom.cfr.jarPath`로 직접 준비한 `cfr-*.jar` 경로를 지정하세요.)

## 기능

### 1. JAR 파일 열기

탐색기에서 `.jar` 파일을 우클릭 → **Decom: JAR 파일 열기**, 또는 커맨드 팔레트에서 실행합니다.
jar 안의 모든 항목(`.class` 포함)을 원본 바이트 그대로 실제 디스크 캐시 폴더에 풀어내고, 그
폴더를 워크스페이스 폴더로 마운트합니다. 같은 jar를 다시 열면(내용이 바뀌지 않았다면) 캐시를
재사용합니다.

### 2. Class 파일 열람 (읽기 전용)

마운트된 폴더에서 `.class` 파일을 더블클릭하면(또는 우클릭 → **Decom: Class 파일
디컴파일하여 보기**) CFR로 그 자리에서 디컴파일한 소스를 읽기 전용 웹뷰로 보여줍니다. 디스크에
`.java` 파일이 생성되지 않고, 일반 텍스트 문서가 아니므로 설치된 Java 언어 서버가 개입해 (
디컴파일 과정에서 생긴 가짜) 오류를 Problems 패널에 띄우는 일도 없습니다. 내부/익명 클래스는
같은 디렉터리의 형제 `.class` 파일을 CFR이 자동으로 찾아 본문에 병합해서 보여줍니다. JAR와
무관한 독립 `.class` 파일도 동일하게 열람할 수 있습니다.

### 3. JAR 내부 리소스/라이브러리 수정 후 저장

`.class`를 제외한 나머지 파일(설정 파일, XML, properties, 텍스트, `BOOT-INF/lib/*.jar` 같은
내장 라이브러리 등)은 마운트된 폴더 안의 평범한 실제 파일입니다. VSCode 에디터로 직접
수정하거나, 파일 탐색기에서 다른 jar로 교체(복사/붙여넣기)하거나, 새 파일을 추가/삭제해도
됩니다. 원하는 만큼 수정한 뒤 루트 폴더 우클릭 → **Decom: 변경사항을 JAR에 저장**을 실행하면:

1. 저장 전 확인 대화상자를 띄웁니다.
2. 해당 jar를 처음 수정하는 시점에 `<원본jar>.decom-bak` 백업을 한 번 생성합니다.
3. 캐시 폴더의 현재 상태(수정/추가/삭제 전부)로 원본 jar를 통째로 다시 만듭니다. Decom 내부
   관리 파일(`.decom/`, `.vscode/`)은 제외됩니다.

### 4. JAR 내부 검색

JAR을 열면 내용이 실제 디스크 폴더로 존재하고 워크스페이스 폴더로 마운트되므로, VSCode 기본
검색(`Ctrl+Shift+F` 전체 검색, `Ctrl+P` 파일 검색)이 별도 설정 없이 그대로 작동합니다. (단,
`.class`는 바이너리라 텍스트 내용 검색 대상에서는 자연히 제외되고 파일명 검색만 됩니다.)

## 기타 명령

- **Decom: JAR 다시 추출 (새로고침)** - jar가 외부에서 변경된 경우 다시 추출합니다. **주의**:
  아직 "JAR에 저장"하지 않은 로컬 편집 내용은 원본 바이트로 덮어써서 사라집니다.
- **Decom: JAR 마운트 해제** - 워크스페이스에서 폴더만 제거(캐시/원본 jar는 유지)

## 설정

| 설정 | 설명 |
| --- | --- |
| `decom.cfr.jarPath` | CFR jar 경로 직접 지정 (비우면 자동 다운로드) |
| `decom.java.executable` | CFR 실행용 `java` 경로 |
| `decom.classpath.extra` | 디컴파일 시 CFR에 추가로 전달할 classpath (더 정확한 디컴파일을 위한 외부 참조 jar/디렉터리) |
| `decom.cfr.options` | CFR에 전달할 추가 CLI 옵션 |

## 개발

```
npm install
npm run compile   # 또는 npm run watch
```

`F5`로 확장 개발 호스트(Extension Development Host)를 실행하여 테스트할 수 있습니다.

## 알려진 제한사항

- 디컴파일된 소스는 원본과 100% 동일하지 않을 수 있습니다(변수명, 일부 최적화된 구문 등). 열람
  전용이므로 이 점이 실제 JAR 동작에 영향을 주지는 않습니다.
- "JAR에 저장"은 캐시 폴더 전체를 기준으로 jar를 다시 만드는 방식이라, zip 안 물리적 항목
  순서는 보존되지 않습니다(라이브러리인 adm-zip이 저장 시 재정렬함). JVM/Spring Boot 등은
  central directory로 항목을 찾기 때문에 순서는 실행에 영향을 주지 않습니다.
