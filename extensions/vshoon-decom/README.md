# Decom — 읽기 전용 JAR/Class 탐색기

JAR를 압축 해제하거나 워크스페이스에 마운트하지 않고 VShoon 기본 Explorer에서 폴더처럼 탐색한다.
`.class` 파일은 CFR로 디컴파일해 읽기 전용으로 보여준다.

## 요구사항

- CFR 실행에 사용할 JDK와 `java` 명령이 필요하다. 경로가 다르면 `decom.java.executable`로 지정한다.
- 디컴파일러는 [CFR](https://github.com/leibnitz27/cfr)을 사용한다. 최초 사용 시 GitHub 릴리스에서
  내려받아 SHA-256 무결성을 확인한 뒤 확장 저장소에 캐시한다. 오프라인 환경에서는
  `decom.cfr.jarPath`에 준비한 `cfr-*.jar` 경로를 지정한다.

## JAR 탐색

Explorer의 로컬 `.jar` 행에서 펼침 아이콘을 누르면 ZIP entry 목록을 메모리에 인덱싱하고
`vshoon-jar:` 읽기 전용 가상 파일 시스템으로 표시한다. 전체 JAR를 디스크 폴더에 풀지 않으며
워크스페이스 폴더 목록도 바꾸지 않는다.

파일 내용은 열 때 해당 entry만 읽는다. JAR 내부의 JAR도 펼칠 수 있으며, 중첩 JAR는 그 노드를
펼치는 시점에만 바이트를 읽어 별도 가상 트리로 만든다.

## Class 열람

JAR를 펼치면 5초의 유휴 시간 뒤 JAR 전체를 CFR/JVM 한 번으로 일괄 디컴파일한다. 클래스마다 JVM을
새로 띄우지 않으며, 완료 마커가 있는 JAR는 다음 실행에서 백그라운드 작업 자체를 건너뛴다. 사용자가
클래스를 직접 열거나 에디터를 전환하거나 커서·선택을 움직이면 진행 중인 일괄 작업을 중단하고 해당
클래스의 outer/inner 묶음만 먼저 처리한다. 중단한 일괄 작업은 다시 5초 동안 유휴 상태일 때 시작한다.

`Foo$Bar.class`처럼 내부 클래스를 열면 CFR가 묶음 전체를 한 텍스트로 만들므로 바깥 클래스인
`Foo`의 문서가 열린다. 묶음 하나당 디컴파일은 한 번만 실행한다.

결과는 `vshoon-decom:` 읽기 전용 Java 문서로 열리므로 일반 편집기의 줄 번호, 문서 검색, 개요와
선언 이동을 사용할 수 있다. 선언 이동은 캐시가 준비된 같은 JAR 안에서 호출의 수신 클래스, 인자 수,
리터럴·변수에서 추론한 인자 타입을 선언과 비교한다. 오버로드처럼 대상을 하나로 확정할 수 없으면
점수가 같은 후보 목록이 열린다. 후보는 JAR별 타입 인덱스에서 찾으므로 클래스가 많은 JAR에서도 한 번의
이동이 캐시 전체를 읽지 않는다.
JAR와 무관한 로컬 `.class`도 같은 방식으로 열 수 있다.

디컴파일 결과는 확장 전용 저장소에 영속 캐시한다. 클래스 묶음, 원본 JAR 내용, CFR, 옵션이 같으면
재실행 후에도 결과를 재사용하며, 준비된 클래스는 임시 파일을 다시 만들지 않고 대기열도 거치지 않고
바로 열린다. 재시작 후에는 원본 JAR의 크기·수정 시각을 먼저 확인하므로 JAR 전체를 다시 읽어
SHA-256을 계산하지 않는다. 크기나 수정 시각이 달라지면 오래된 결과를 검색이나 열기에 사용하지 않는다.

## VSearch 연동

VSearch의 `JAR 내부 포함`을 켜면 준비된 디컴파일 캐시를 일반 파일 결과와 함께 검색한다. 결과를
열면 같은 읽기 전용 Java 문서의 일치 줄로 이동한다. 분석 중인 클래스가 있으면 상태 표시줄에 남은
대기 수를 표시하므로, 분석이 끝난 뒤 같은 검색을 다시 실행하면 새 결과가 포함된다.

JAR 검색 결과의 미리보기는 읽기 전용이다. 단일 바꾸기, 전체 바꾸기, 미리보기 저장은 UI와 확장
호스트 양쪽에서 거부한다.

## 읽기 전용 정책

- JAR 내부의 텍스트, XML, properties와 기타 리소스는 열람만 가능하다.
- 가상 파일 시스템은 쓰기, 생성, 삭제, 이름 변경을 모두 거부한다.
- `decom.saveToJar`, JAR 재생성, `.decom-bak` 백업, 마운트 해제 기능은 등록하지 않는다.
- `Decom: JAR 내용 새로고침`은 원본을 변경하지 않고 메모리 인덱스와 디컴파일 캐시만 비운다.

## 설정

| 설정 | 설명 |
| --- | --- |
| `decom.cfr.jarPath` | CFR JAR 경로 직접 지정. 비우면 자동 다운로드 |
| `decom.java.executable` | CFR 실행용 `java` 경로 |
| `decom.classpath.extra` | CFR에 추가로 전달할 외부 JAR 또는 디렉터리 classpath |
| `decom.cfr.options` | CFR에 전달할 추가 CLI 옵션 |
| `vshoon.decom.precompileOnExpand` | JAR를 펼쳤을 때 백그라운드 사전 디컴파일 여부 |
| `vshoon.decom.precompileMaxClasses` | 일괄 사전 디컴파일할 JAR의 최대 클래스 묶음 수. 기본 5,000 |
| `vshoon.decom.cacheMaxSizeMb` | 영속 소스 캐시 최대 용량. 기본 512MB |
| `vshoon.decom.decompileTimeoutSec` | 디컴파일 실행이 진행되지 않은 채 기다릴 최대 시간(초). 기본 120, 0이면 제한 없음 |

`Decom: 백그라운드 디컴파일 취소`와 `Decom: 디컴파일 소스 캐시 삭제` 명령으로 작업과 저장소를
직접 정리할 수 있다.

## 알려진 제한

- 대응하는 `-sources.jar`를 자동 연결하지 않는다.
- 디컴파일 결과는 원본 소스와 완전히 같지 않을 수 있다.
- 선언 이동은 준비된 같은 JAR의 직접 호출만 제한적으로 분석한다. 연쇄 호출의 반환 타입, 모든 generic
  타입, JVM descriptor·상속·동적 호출을 분석하는 완전한 Java 의미 분석과 사용처 검색은 제공하지 않는다.
- 클래스 수 상한을 넘은 JAR는 일괄 처리를 생략하며 클래스를 직접 열 때 디컴파일한다.
- 진행이 멈춘 디컴파일은 시간 제한에 걸려 중단되며, 중단된 일괄 작업은 같은 창에서 자동으로 다시
  실행하지 않는다.
- 중첩 JAR는 펼칠 때 해당 JAR 하나를 메모리에 읽는다. 로컬 최상위 JAR는 전체를 메모리에 읽지 않는다.
