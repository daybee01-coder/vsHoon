# 변경 이력

이 파일의 형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/) 를 따르고,
버전은 [유의적 버전](https://semver.org/lang/ko/) 을 따른다.

## [Unreleased]

### 고침

- **Oracle 읽기 전용 연결이 트랜잭션을 붙들고 있던 문제.** 커넥션이 만들어질 때
  `SET TRANSACTION READ ONLY` 를 걸었는데, 이 구문은 세션 설정이 아니라 **트랜잭션을
  연다.** 끝내는 사람이 없어 커넥션 수명(기본 30분) 내내 열려 있었고, 그 결과
  (1) 조회가 연결 시점의 스냅샷을 봐서 **옛 데이터를 돌려주고**,
  (2) 그 스냅샷을 위한 undo 를 서버가 계속 붙들었다. 이제 명시적 트랜잭션을 열 때
  걸어서 커밋·롤백이 반드시 끝내게 한다. (MySQL·PostgreSQL 은 세션 단위 구문이라 해당 없음)

### 변경 — 운영 부하

- **연결만으로 카탈로그를 훑지 않는다.** 미리 읽는 범위를 스키마 12개 → **기본 스키마 1개**로
  줄이고(`dbconn.metadata.prefetch`), **운영으로 표시한 연결은 연결 직후 미리 읽기를 건너뛴다.**
  자동 완성·트리를 쓸 때 그 스키마만 읽으므로 기능은 그대로다.
- **예상 행 수는 기본 꺼짐**(`dbconn.metadata.estimateRows`). MySQL/MariaDB 에서
  `information_schema.TABLES.TABLE_ROWS` 는 `innodb_stats_on_metadata` 가 켜져 있으면
  스키마의 모든 테이블 통계를 다시 표집한다.

### 변경

- **연결 추가/편집을 한 화면으로** — QuickPick/InputBox 를 여덟 단계로 잇던 마법사를
  폼 하나로 바꿨다. 종류를 고르면 포트·기본 사용자·데이터베이스 칸 이름이 따라오고,
  `Ctrl+Enter` 로 저장, `Esc` 로 취소한다. 비밀번호는 저장/테스트 요청에 실려 확장으로
  갈 때만 오가며, 웹뷰 상태에는 남지 않는다.
  VShoon에서는 화면이 **모달 편집기**로 열려 기존 SQL 편집기와 창 배치를 유지하고,
  일반 VS Code에서는 웹뷰 편집기 탭으로 안전하게 대체된다.
- **연결 줄이 흔들리지 않는다** — 연결 항목은 연결 여부와 상관없이 늘 펼칠 수 있다.
  예전에는 하나가 연결되는 순간 그 줄에 화살표가 생기면서 목록 전체가 오른쪽으로 밀렸다.
  연결 전에 펼치면 안내 한 줄이 나온다.
- **연결은 더블클릭에서만 접속한다** — 트리에서 한 번 클릭은 고르기일 뿐이다.
  목록을 훑는 것만으로 세션이 열리던 것을 테이블 상세와 같은 규칙으로 맞췄다.
- **연결 아이콘의 배경 제거** — 로고 뒤의 흰 판을 없애고 로고가 상자를 채우게 했다.
  환경 점이 놓일 자리는 로고에서 도려내, 테마에 상관없이 점이 또렷하게 보인다.

### 추가

- **URL / 호스트 두 가지 입력 방식** — 연결 화면의 `입력 방식` 라디오로 고른다.
  **URL** 을 고르면 종류·호스트·포트·데이터베이스 칸이 사라지고 URL 칸 하나만 남는다
  (그 값들은 URL 에서 나오므로 같은 정보를 두 곳에 두지 않는다). 타이핑·붙여넣기와 동시에
  읽어 `PostgreSQL · db.example.com:5432 · orders` 처럼 요약을 보여 주고, 못 읽으면 그 자리에
  이유가 뜬다. **호스트 직접 입력** 으로 되돌리면 방금 URL 에서 나온 값이 칸에 그대로 담겨
  있어 이어서 고칠 수 있고, 반대로 호스트 방식에서 URL 로 바꾸면 지금 칸 값으로 URL 이
  만들어진다.
  `mysql://` · `mariadb://` · `postgresql://` · `oracle://` 과 `jdbc:` 형태
  (`jdbc:oracle:thin:@//host:1521/service`, `jdbc:oracle:thin:@host:1521:SID` 포함)를 읽는다.
  `sslmode=require` 는 "암호화만", `verify-full` 은 검증까지로 옮겨 붙고, 알아보지 못한
  파라미터는 무시하되 이름을 알려 준다. URL 에 자격 증명이 있으면 채워 주지만, 손으로 고쳐
  적은 사용자·비밀번호는 덮어쓰지 않는다.
  저장·연결 테스트 직전에 확장이 URL 을 한 번 더 읽는다 — 마지막 타자와 저장 사이의 틈에
  낡은 값이 저장되는 길을 남기지 않는다. **복사** 단추와 연결 우클릭의 `연결 URL 복사` 는
  지금 설정을 URL 한 줄로 만들어 준다(비밀번호는 절대 넣지 않는다).
  트리 제목 메뉴의 `URL 로 커넥션 추가` 로 곧장 시작할 수도 있다.
- **새 SQL 편집기가 파일로 만들어진다** — `DBConn: 새 SQL 편집기` 는 이름 없는 문서 대신
  확장의 보관 폴더에 `주문DB_2026-08-21_143005.sql` 같은 파일을 만들어 연다. 편집이 멈추면
  1.2초 뒤 자동 저장되므로 창을 닫아도, VS Code 가 죽어도 쿼리가 남는다.
  기본 위치는 확장의 전역 저장소(`globalStorage/queries`)이고 `dbconn.scripts.folder` 로
  옮길 수 있다(`~` 는 홈으로 풀린다). 보관된 목록은 `DBConn: 보관된 쿼리 열기`,
  폴더 자체는 `DBConn: 쿼리 보관 폴더 열기` 로 연다.
  자동 저장은 **이 폴더 안의 파일에만** 적용된다 — 사용자의 다른 파일이 저장되는 시점을
  확장이 가로채지 않는다. 예전처럼 이름 없는 문서로 열려면
  `dbconn.scripts.newQueryLocation` 을 `untitled` 로 둔다.
- **편집기마다 연결 지정** — SQL 편집기 하나에 연결 하나를 붙여 둔다. 상태바를 누르거나
  편집기 우클릭 → `이 편집기의 연결 지정` 으로 고르면, 그 파일의 실행·자동 완성은 활성
  연결과 무관하게 언제나 그 DB 로 나간다. 지정된 편집기는 상태바에 압정(📌)이 붙고,
  지정이 있는데 아직 접속 전이면 실행할 때 그 연결을 연다(전역 기본으로 넘어가지 않는다).
  지정은 워크스페이스에 저장되고, 이름 없는 문서를 파일로 저장해도 따라간다.
- **쿼리 이력 사이드바** — 사이드바에 `쿼리 이력` 뷰가 생겼다. 날짜별로 묶여 오늘 것이
  펼쳐진 채로 열리고, 각 줄에 연결·시각·소요·행 수(또는 오류)가 붙는다. 클릭하면 편집기에
  넣고, 줄 끝 단추로 새 편집기로 열기(그때 쓰던 연결이 그 편집기에 지정된다) · SQL 복사 ·
  삭제를 한다. 기존 명령 팔레트 검색(`쿼리 실행 이력`)은 그대로다.
- **스크롤로 이어 조회** — 결과 그리드를 맨 아래까지 내리면 다음 묶음을 **기존 결과 뒤에
  이어 붙인다**. 보고 있던 위치와 선택은 그대로 유지된다. 자동 조회는
  `dbconn.execution.maxLoadedRows`(기본 50,000행)에서 멈추고, 그 뒤로는 툴바의
  `더 불러오기` 단추로 계속 가져온다. `dbconn.execution.autoLoadMore` 로 끌 수 있다.
- **행 제한 즉시 조절** — 결과 툴바에 행 제한 선택 상자가 생겼다. 바꾸면 설정
  (`dbconn.execution.maxRows`)에 저장되고 보고 있던 결과도 새 크기로 다시 읽는다.
  명령 팔레트의 `결과 행 제한 변경` 과 결과 패널 제목 단추에서도 같은 일을 한다.
- **최근 SQL 편집기 열기** — 최근에 연 `.sql` 파일만 모아 보여주는 목록. 연결 우클릭 메뉴,
  연결 뷰 제목의 `…` 메뉴, SQL 편집기 우클릭 메뉴에 있다. 내용을 복사해 두지 않고 경로만 기억한다
  (내용을 지키는 일은 초안 캐시가 맡는다).
- **연결 복사 · 붙여넣기**(`Ctrl+C` / `Ctrl+V`) — 비슷한 연결을 여럿 만들 때. 붙여 넣은
  자리가 목적지가 되고, 이름에는 겹치지 않는 `(복사본)` 꼬리가 붙는다. 비밀번호는 화면과
  클립보드를 거치지 않고 자격 증명 저장소 안에서만 복제되며, 시스템 클립보드는 건드리지
  않는다(내부 호스트명·계정이 새어 나가지 않게).
- **`F2` 로 이름 변경** — 트리에서 연결 또는 폴더를 고르고 `F2`. 무엇을 바꿀지는
  선택된 항목을 보고 정한다. 연결 이름은 표시용이라 바꿔도 세션이 끊기지 않는다
  (상태바 표시도 함께 갱신된다).

### 수정

- **보관 폴더의 쿼리에서 자동 완성과 자동 저장이 동작하지 않던 문제** — 전역 저장소
  (`globalStorage`) 안의 파일은 `file` 이 아니라 **`vscode-userdata` 스킴**으로 열린다.
  자동 완성 등록(`scheme: 'file'`), 자동 저장 대상 판정, 최근 목록이 모두 스킴을 `file` 로
  못 박고 있어서, 정작 이 도구가 만든 쿼리 파일만 조용히 빠졌다. Ctrl+Space 를 눌러도
  VS Code 의 단어 추천만 뜨고, 타이핑한 내용이 저장되지 않았다.
  자동 완성은 스킴을 보지 않고 SQL 문서면 돕도록 바꿨고, 나머지 판정도 스킴 가정을 걷어냈다.
  아울러 **기본 보관 위치를 홈 디렉터리의 `.vscode/dbconn/queries`** 로 옮겼다 — 평범한
  파일 경로라 이런 함정이 없고, 탐색기로 찾아가기도 쉽다. 예전 위치에 만들어 둔 쿼리는
  처음 실행할 때 새 폴더로 복사한다(원본은 지우지 않는다).
- **연결이 닫혀 있어도 자동 완성이 테이블을 제안한다** — 편집기에 연결을 지정하면서
  "지정된 연결이 아직 열려 있지 않으면 아무것도 제안하지 않는" 상태가 생겼다. 창을 다시
  켠 직후처럼 세션이 없을 때 Ctrl+Space 가 키워드만 내놓던 원인이다.
  스키마 캐시는 연결이 끊겨도 남아 있으므로, 세션이 없으면 마지막으로 읽어 둔 스냅샷으로
  제안한다. 캐시조차 없으면 목록 맨 위에 **"…에 연결"** 항목을 띄워 이유를 알리고 그
  자리에서 연결할 수 있게 했다(글자는 바뀌지 않는다).
  아울러 비밀번호 입력을 취소해 열리지 않은 연결에는 편집기를 붙이지 않는다 — 붙여 두면
  그 편집기가 아무 연결도 쓰지 못하는 상태로 남았다.
- **결과 셀 더블클릭이 다시 동작한다** — 첫 번째 누름에서 선택 강조를 반영하려고 본문을
  다시 그리는 바람에 두 번 누른 자리의 DOM 노드가 서로 달라졌고, 브라우저가 `dblclick` 을
  공통 조상에 보내면서 셀을 찾지 못했다. 그래서 편집이 `F2`/`Enter` 로만 열렸다.
  더블클릭 판정을 그리드가 직접 하도록 바꿔, 편집 가능한 셀은 편집이, 그 밖의 셀은 값
  전체 보기가 열린다.

## [0.1.0] — 첫 배포 준비

### 연결

- MySQL · MariaDB · PostgreSQL · Oracle 연결 프로필. 비밀번호는 OS 자격 증명 저장소(SecretStorage)에만 저장한다.
- **방언별 아이콘** — 제품 로고로 어떤 DB 인지, 연결됐는지, 어떤 환경인지를 아이콘 하나로 보여준다. 트리와 연결 선택 목록에서 같은 그림을 쓴다. 로고는 Devicon(MIT)에서 가져왔고, 각 제품 소유자의 상표다.
- **환경 구분**(개발 · 스테이징 · 운영) — 아이콘의 환경 점, 상태바 배경, 결과 패널 배지가 함께 물든다.
- **연결 테스트** — 저장 전에 실제로 접속해 본다. 마법사 마지막 단계와 트리 우클릭 양쪽에서.
- **폴더** — 연결을 계층으로 묶고, 끌어다 놓아 옮긴다. 폴더를 지워도 연결은 상위로 올라올 뿐 사라지지 않는다.
- TLS 설정(시스템 신뢰 저장소 · 사설 CA · 검증 끄기 경고), 읽기 전용 연결.

### 실행

- `Ctrl+Enter` 커서 위치 구문 실행, `Ctrl+Shift+Enter` 전체 실행, `Ctrl+Escape` 서버 측 취소.
- 편집기 하나가 결과 탭 묶음 하나를 갖고, 탭 고정(📌)으로 남겨 비교한다.
- **실행 계획**(`Ctrl+Alt+E`) — 방언별 EXPLAIN / DBMS_XPLAN. 측정(ANALYZE)은 SELECT 에만 허용하고 확인을 받는다.
- **쿼리 실행 이력** — SQL 과 결과 요약만 남긴다(결과 데이터는 저장하지 않음). 목록에서 편집기로 삽입.
- **SQL 초안 캐시** — 저장하지 않은 편집기 내용을 주기적으로 보관하고, 다음 실행에서 복구를 제안한다.

### 결과 그리드

- 가상 스크롤, 셀 **블록 선택**(행 번호 클릭·드래그·`Ctrl+A`), TSV 복사로 블록 구조 유지.
- 컬럼 헤더 클릭 정렬 — 화면에 다 있으면 즉시, 잘렸으면 서버에서 전체 정렬.
- **페이징** — `maxRows` 를 넘는 결과를 쪽 단위로 넘겨 본다.
- 컬럼 경계 드래그로 너비 조절(더블클릭 시 내용에 맞춤).
- **셀 값 뷰어**(`Alt+Enter`) — 한 줄로 잘린 긴 값·JSON 을 통째로 본다.
- 단일 테이블 조회에서 **직접 편집** — 셀 수정 · 행 삭제 · **새 행 추가**. 별칭은 원본 컬럼으로 이어지고, 가공된 값은 편집 대상에서 빠진다.
- CSV · JSON 내보내기.

### 스키마

- 스키마 인식 자동 완성(`Ctrl+Space`), 반복 입력 시 테이블 → 뷰 → 시퀀스 → 루틴 분류 순환.
- **객체 상세 정보**(트리에서 더블클릭) — 속성 · 컬럼 · 인덱스 · **외래 키(양방향)** · DDL. 서버가 DDL 을 주지 않으면 근사 DDL 을 만들고 근사임을 표시한다.
- 외래 키의 상대 테이블로 이동.

### 안전장치

- 커넥션 풀: 반납 강제, 열린 트랜잭션은 풀로 돌아가지 않음, 좀비 대여 자동 회수, 유휴 트랜잭션 자동 롤백.
- 위험 구문 확인. **운영 연결에서는 변경 구문 실행 전 대상 이름을 직접 입력**해야 한다.
- 그리드 편집은 운영 연결에서 설정과 무관하게 항상 확인한다.
- 값은 언제나 바인드 파라미터로, 식별자는 언제나 인용을 거쳐 조립한다.

### 개발

- 순수 로직 단위 테스트 247개.
- Docker 기반 **드라이버 통합 테스트** — 방언별 카탈로그·계획·페이징·편집 SQL 을 실제 서버에 던져 확인한다.
- ESLint(타입 인식 규칙) + `tsc --noEmit` + esbuild 번들.
