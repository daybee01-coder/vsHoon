# DBConn

VS Code 안에서 MySQL · MariaDB · PostgreSQL · Oracle 을 다루는 데이터베이스 클라이언트.

메인 에디터에서 SQL 을 쓰고 `Ctrl+Enter` 로 실행하면, 하단 패널에 결과가 뜬다.
`Ctrl+Space` 는 실제 스키마를 읽어 테이블·컬럼·별칭을 제안하고,
연달아 누르면 테이블 → 뷰 → 시퀀스 → 함수 순으로 분류를 넘겨 준다.

---

## 사용법

| 조작 | 동작 |
| --- | --- |
| `Ctrl+Enter` | 커서가 있는 문장 실행 (선택 영역이 있으면 그것만) |
| `Ctrl+Shift+Enter` | 문서 전체 또는 선택 영역의 모든 문장 실행 |
| `Ctrl+Space` | 자동 완성 (같은 자리에서 반복하면 객체 분류 순환) |
| `Ctrl+Alt+E` | 커서 위치 구문의 실행 계획 보기 |
| `Ctrl+Escape` | 실행 중인 쿼리 취소 (서버 측에서도 중단) |

세미콜론이 없어도 되고, 문장 중간 어디에 커서가 있어도 된다.
실행되는 범위는 잠깐 하이라이트되어 눈으로 확인할 수 있다.

트리에서 테이블·뷰·시퀀스를 **더블클릭**하면 상세 정보 화면이 열리고,
저장하지 않은 SQL 초안은 자동으로 캐시되어 창을 닫아도 다시 열 수 있다.

### 시작하기

1. 활동 표시줄의 **Database** 아이콘 → **연결 추가**
2. **별도 창**으로 뜨는 연결 화면에서 종류 · **환경(개발/스테이징/운영)** · 호스트 ·
   계정을 **한 번에** 채운다 (`Ctrl+Enter` 로 저장, `Esc` 로 취소)
3. 저장 전에 **연결 테스트** 로 실제 접속을 확인한다 — 몇 번이든 반복할 수 있다
4. 연결 후 **새 SQL 편집기** 로 쿼리 작성 — 파일로 만들어져 자동 저장된다
   (아래 [쿼리 보관](#쿼리-보관--새-편집기는-파일로))

접속 정보를 URL 한 줄로 받았다면 연결 화면의 **URL** 칸에 붙여 넣고 **적용**을 누르면
아래 칸이 한꺼번에 채워진다 (아래 [URL 로 연결 만들기](#url-로-연결-만들기)).

## 편집기마다 연결 지정

**SQL 편집기 하나에 연결 하나를 붙여 둔다.** 개발과 운영 쿼리를 나란히 열어 두고
오갈 때, 활성 연결이 하나뿐이면 창을 옮길 때마다 연결을 바꿔야 하고 결국 한 번은
엉뚱한 DB 로 실행된다.

- 상태바의 연결 항목을 누르거나, SQL 편집기 우클릭 → **이 편집기의 연결 지정** 으로 고른다.
  트리에서 **새 SQL 편집기** 로 연 창은 그 연결이 처음부터 지정돼 있다.
- 지정된 편집기는 상태바에 압정(📌)이 붙는다. 전역 기본 연결을 바꿔도 이 창의 실행과
  자동 완성은 지정된 DB 로 나간다.
- 지정이 있는데 아직 접속 전이면, 실행할 때 **그 연결을 연다.** 전역 기본으로 조용히
  넘어가지 않는다 — 다른 DB 로 실행되느니 멈추는 편이 낫다.
- 지정을 풀려면 같은 목록에서 **이 편집기의 지정 해제** 를 고른다. 지정이 없는 편집기는
  전역 기본 연결을 따른다(예전과 같은 동작).
- 지정은 워크스페이스에 저장되어 창을 닫았다 열어도 남고, 이름 없는 문서를 파일로
  저장해도 따라간다. 연결을 삭제하면 그 연결을 가리키던 지정도 함께 사라진다.

## URL 로 연결 만들기

접속 정보는 대개 URL 한 줄로 돌아다닌다 — 위키의 `postgresql://app@db-prod:5432/orders`,
설정 파일의 JDBC 문자열, `docker-compose` 의 환경 변수. 그걸 칸마다 나눠 다시 타이핑하면
옮겨 적다 틀리기 좋다.

연결 화면의 **입력 방식** 라디오로 고른다.

| 방식 | 화면 |
| --- | --- |
| **호스트 직접 입력** | 종류 · 호스트 · 포트 · 데이터베이스를 칸으로 (기본) |
| **URL** | 그 칸들이 사라지고 URL 한 줄만. 값은 URL 에서 나온다 |

- URL 방식에서는 타이핑·붙여넣기와 동시에 읽어 `PostgreSQL · db.example.com:5432 · orders`
  처럼 요약을 보여 준다. 못 읽으면 그 자리에 이유가 뜬다.
- 두 방식은 같은 값을 공유한다. URL 로 채운 뒤 **호스트 직접 입력** 으로 돌아가면 그 값이
  칸에 담겨 있어 이어서 고칠 수 있고, 반대로 바꾸면 지금 칸 값으로 URL 이 만들어진다.
- 사용자 · 비밀번호 칸은 두 방식 모두 그대로 있다. URL 에 자격 증명이 들어 있으면 채워
  주지만, 손으로 고쳐 적은 값은 덮어쓰지 않는다.
- 저장 · 연결 테스트 직전에 확장이 URL 을 **한 번 더 읽는다.** 마지막 타자와 저장 사이의
  짧은 틈에 낡은 값이 저장되는 길을 남기지 않기 위해서다.
- 트리 제목의 `…` 메뉴 → **URL 로 커넥션 추가** 로 URL 부터 시작할 수도 있다.
- **복사** 단추(와 연결 우클릭 → **연결 URL 복사**)는 지금 설정을 URL 한 줄로 만든다.
  **비밀번호는 절대 담기지 않는다.**

읽는 형태:

| 예 | |
| --- | --- |
| `mysql://app:secret@db:3306/orders` | 사용자 · 비밀번호 · 포트 · DB |
| `postgresql://app@db/orders?sslmode=require` | 포트를 생략하면 방언 기본값 |
| `oracle://system@ora:1521/XEPDB1` | 기본은 서비스 이름, `?connectType=sid` 로 SID |
| `jdbc:mariadb://db:3306/orders?user=app` | `jdbc:` 접두어와 질의 문자열의 자격 증명 |
| `jdbc:oracle:thin:@//ora:1521/XEPDB1` | Oracle JDBC 서비스 이름 형태 |
| `jdbc:oracle:thin:system/pw@ora:1521:XE` | Oracle JDBC SID 형태 (앞의 `user/password` 포함) |

`sslmode` · `ssl` 은 TLS 설정으로 옮겨 붙는다. `require` 는 PostgreSQL 정의대로
"암호화는 하되 인증서는 보지 않는다"로, `verify-ca` · `verify-full` 은 검증까지 켠다.
URL 이 TLS 를 말하지 않으면 화면의 설정을 건드리지 않는다.
알아보지 못한 파라미터(`serverTimezone` 등)는 반영하지 않고 **이름을 알려 준다** —
조용히 삼키면 "URL 에 넣었는데 왜 안 먹지"가 된다.

## VS Code 에서 커넥션 가져오기

정품 VS Code 에서 쓰던 연결이 이 창에 보이지 않는 이유는 두 가지다. 앱 데이터 폴더가
다르고(`%APPDATA%\Code` 와 제품 폴더), 확장 ID 도 바뀌었다. `globalState` 와
`SecretStorage` 는 둘 다 확장 ID 로 격리되므로, 같은 기계·같은 계정이라도 서로의 저장소를
볼 수 없다. 14개를 손으로 다시 입력하지 않도록 옮겨 오는 명령을 둔다.

트리 제목의 `…` 메뉴 → **VS Code 에서 커넥션 가져오기** (명령 팔레트에도 같은 이름).
연결이 하나도 없을 때는 빈 화면의 안내에서도 바로 부를 수 있다.

- 살펴보는 곳은 `Code` · `Code - Insiders` · `VSCodium` 의
  `User/globalStorage/state.vscdb` 이고, 옛 확장 ID(`dbconn.dbconn`)도 함께 찾는다.
- 원본이 여러 곳이면 어디서 가져올지 먼저 고르고, 그다음 가져올 연결을 체크한다.
  **폴더 구조도 함께 온다** — 비어 있던 폴더까지 되살려 트리 모양이 그대로 남는다.
- 폴더 · 이름 · 접속 정보가 모두 같은 연결은 처음부터 선택이 풀려 있다. 목록을 확인만
  하고 넘어가도 같은 연결이 두 개로 늘어나지 않는다. 이름만 겹치면 `(복사본)` 을 붙인다.
- 원본은 **읽기만 한다.** 옛 설치본의 프로필도 비밀번호도 그대로 남으므로, 되돌리려면
  가져온 연결을 지우면 된다.
- 정품 VS Code 가 켜져 있어도 된다. 저장소를 임시 폴더로 복사해서 읽기 때문에 파일을
  붙잡고 있어도 되고, 아직 `-wal` 에만 있는 최근 변경까지 반영된다.

저장소를 통째로 옮기고 싶으면(연결 · 폴더 · 쿼리 이력 · 보관한 SQL 목록까지, 고르는 화면
없이) 리포지토리 스크립트를 쓴다. **앱을 닫고** 실행한다 — 실행 중이면 앱이 메모리에 든
값을 나중에 다시 써서 덮어쓸 수 있다. 대상 저장소는 실행 직전에 자동으로 백업된다.

```
npm run dbconn:copy-store -- --dry-run   # 무엇이 바뀔지만 본다
npm run dbconn:copy-store                # 실제로 복사
```

**비밀번호도 함께 온다** — Windows 에서, 같은 사용자 계정으로 로그인해 있을 때.
저장 경로가 두 겹이기 때문이다: 비밀번호는 Electron `safeStorage` 가 AES-256-GCM 으로
암호화하고, 그 키는 앱 데이터 폴더의 `Local State` 안에서 DPAPI 가 현재 사용자 계정으로
보호한다. 그래서 파일만 다른 계정이나 다른 기계로 옮겨서는 읽히지 않는다 —
이 명령이 되돌릴 수 있는 것도 같은 계정으로 켜져 있는 동안뿐이다.
macOS · Linux 는 키체인과 시크릿 서비스가 앱 신원을 확인하므로 비밀번호는 넘어오지
않는다. 그 경우 확인을 한 번 받고 연결 정보만 가져오며, 비밀번호는 처음 접속할 때
다시 물어본다.

## 실행 계획

`Ctrl+Alt+E` 로 커서 위치 구문의 계획을 본다. 계획 탭은 기존 결과 탭을 밀어내지 않으므로
결과와 계획을 나란히 두고 비교할 수 있다.

| 방언 | 방식 |
| --- | --- |
| MySQL · MariaDB | `EXPLAIN` (표) / `EXPLAIN ANALYZE` (트리 텍스트) |
| PostgreSQL | `EXPLAIN (VERBOSE, COSTS, FORMAT TEXT)` / 측정 시 `ANALYZE, BUFFERS` 추가 |
| Oracle | `EXPLAIN PLAN FOR` → `DBMS_XPLAN.DISPLAY` (같은 세션에서 두 구문) |

**실행 계획 측정(ANALYZE)** 은 구문을 *실제로 실행한다.* 그래서:

- SELECT 가 아니면 거부한다. 계획을 보려다 UPDATE 가 도는 사고는 없어야 한다.
- 실행 전에 확인 대화상자를 띄운다.
- Oracle 은 측정을 지원하지 않고 예상 계획만 보여준다 (사용자 SQL 에 힌트를 주입해야 하므로 제외).

트랜잭션이 열려 있으면 그 커넥션에서 계획을 본다 — 다른 커넥션에서는 아직 커밋되지 않은
스키마 변경이 보이지 않기 때문이다. Oracle 의 `PLAN_TABLE` 임시 행은 조회 후 롤백으로 정리한다.

## 쿼리 실행 이력

실행한 SQL 과 결과 요약(시각 · 연결 · 소요 · 행 수 · 오류)을 남긴다.
**결과 데이터는 저장하지 않는다** — 저장소가 커지는 문제보다, 조회한 개인정보가
이력에 오래 남는 쪽이 훨씬 위험하다.

- 기록 대상: 편집기 실행 · 트리 미리보기 · **그리드 편집(UPDATE/DELETE)** · 실행 계획.
  그리드 편집은 값이 채워진 미리보기 문장으로 남아 "언제 무엇을 바꿨는지" 되짚을 수 있다.
- 사이드바의 **쿼리 이력** 뷰에 항상 떠 있다. 날짜별로 묶여 오늘 것이 펼쳐진 채로 열리고,
  줄마다 연결 · 시각 · 소요 · 행 수(또는 오류)가 붙는다. 마우스를 올리면 SQL 전문을 본다.

  | 조작 | 동작 |
  | --- | --- |
  | 항목 클릭 | 열려 있는 SQL 편집기의 커서 위치에 삽입 (없으면 새 편집기) |
  | **새 편집기로 열기** | 새 SQL 편집기로 열고 **그때 쓰던 연결을 그 편집기에 지정** |
  | **SQL 복사** · **이력에서 삭제** | 줄 끝 아이콘 |

- **DBConn: 쿼리 실행 이력** 명령(이력 뷰 제목의 돋보기, 연결 뷰 제목의 시계 아이콘)은
  검색 가능한 목록을 연다. 항목이 많을 때 이름으로 찾는 쪽이 빠르다.
- 같은 연결에서 같은 SQL 을 연달아 실행하면 새로 쌓지 않고 실행 횟수만 센다.
  그러지 않으면 이력이 같은 줄로 도배되어 쓸모가 없어진다.
- 보관 정책은 건수(`dbconn.history.maxEntries`, 기본 200)와 기간
  (`dbconn.history.retentionDays`, 기본 30일). `dbconn.history.enabled` 로 끌 수 있다.

## 쿼리 보관 — 새 편집기는 파일로

**DBConn: 새 SQL 편집기** 는 이름 없는 문서가 아니라 **파일**을 만든다.
이름 없는 문서는 창을 닫는 순간 사라지고 그걸 되살리는 일을 초안 캐시가 떠맡아야 했는데,
애초에 파일로 두면 그 문제가 없다 — 다시 열 수 있고, 검색되고, 원하면 워크스페이스로
옮겨 형상 관리에 넣을 수도 있다.

- 이름은 `주문DB_2026-08-21_143005.sql` — 어느 연결에서 시작했는지와 만든 시각.
  이름순 정렬이 곧 시간순이다.
- **편집이 멈추면 1.2초 뒤 자동 저장된다.** 창을 닫아도, VS Code 가 죽어도 쿼리가 남는다.
  자동 저장은 **보관 폴더 안의 파일에만** 적용된다 — 사용자의 다른 파일이 저장되는 시점을
  확장이 가로채지 않는다 (`dbconn.scripts.autoSave` 로 끌 수 있다).
- 기본 위치는 홈 디렉터리의 **`.vscode/dbconn/queries`** 다
  (윈도우라면 `C:\Users\<계정>\.vscode\dbconn\queries`). 워크스페이스 안에 두면 남의
  저장소에 잡동사니를 만들게 되고, 워크스페이스 없이 연 창에서는 둘 곳이 없어진다.
  확장의 전역 저장소를 쓰지 않는 이유는 그 폴더가 `vscode-userdata` 스킴으로 열려서,
  스킴을 `file` 로 가정한 곳(자동 완성 등록 등)이 그 문서만 건너뛰기 때문이다.

| 명령 | |
| --- | --- |
| **DBConn: 보관된 쿼리 열기** | 폴더에 쌓인 `.sql` 을 최근 수정순으로. 휴지통 아이콘으로 삭제 |
| **DBConn: 쿼리 보관 폴더 열기** | 폴더를 파일 탐색기로 (백업하거나 통째로 옮길 때) |

| 설정 | 기본값 | |
| --- | --- | --- |
| `dbconn.scripts.newQueryLocation` | `folder` | `untitled` 로 두면 예전처럼 이름 없는 문서 |
| `dbconn.scripts.folder` | (비움) | 보관 폴더 경로. 비우면 `~/.vscode/dbconn/queries` |
| `dbconn.scripts.autoSave` | `true` | 보관 폴더 안 파일의 자동 저장 |

폴더를 옮기고 싶으면 `dbconn.scripts.folder` 에 경로를 적는다 (예: `D:/sql`, `~/queries`).
이미 만들어진 파일은 따라가지 않으므로, 바꾸기 전에 **쿼리 보관 폴더 열기** 로 기존 파일을
옮겨 두면 된다.

여기에는 사용자가 쓴 SQL 이 그대로 남는다. 쿼리에 자격 증명을 적는 습관이 있다면
이 파일에도 남는다.

## SQL 초안 캐시

파일로 저장되기 전의 편집 내용과, 이름 없는 문서로 연 쿼리는 여전히 캐시가 지킨다.
DBConn 은 편집 중인 SQL 문서를 1초 간격(디바운스)으로 확장의 전역 저장소에 복사해 둔다.

- 대상은 **untitled 이거나 저장되지 않은 변경이 있는 SQL 문서**뿐이다.
  이미 저장된 파일의 내용은 캐시하지 않는다 — 사용자가 지운 내용이 엉뚱한 곳에 남으면 안 된다.
- **저장하는 순간 캐시에서 지운다.** 그때부터는 원본 파일이 진실이다.
- 다음 실행에서 남은 초안이 있으면 알림으로 알려 준다
  (`dbconn.scripts.restore`: `prompt`(기본) · `auto` · `off`).
  VS Code 의 핫 엑싯이 이미 복원한 초안은 중복으로 열지 않는다.
- **DBConn: 캐시된 SQL 초안 열기** 명령(연결 뷰 제목의 시계 아이콘)으로 언제든 목록을 볼 수 있다.
  목록에서 휴지통 아이콘을 누르면 개별 삭제, **SQL 초안 캐시 비우기** 로 전체 삭제.

보관 정책은 개수(`dbconn.scripts.maxEntries`, 기본 50개)와 기간
(`dbconn.scripts.retentionDays`, 기본 14일)을 함께 본다. 캐시가 부담스러우면
`dbconn.scripts.cache` 로 끌 수 있다.

### 최근 SQL 편집기

**DBConn: 최근 SQL 편집기 열기** — 최근에 연 `.sql` **파일**만 최근 순으로 모아 보여준다.
연결을 우클릭한 메뉴, 연결 뷰 제목의 `…` 메뉴, SQL 편집기 우클릭 메뉴 세 곳에 있다.

VS Code 의 "최근 항목 열기"와 겹쳐 보이지만 다르다. 저기는 워크스페이스와 온갖 파일이
섞여 있어서, 어제 쓰던 쿼리 하나를 찾는 데 쓰기 어렵다.

초안 캐시와도 맡은 일이 다르다. 초안 캐시는 **파일이 아닌 것**을 지키려고 내용을 통째로
보관하고 저장되는 순간 항목을 지운다. 이 목록은 반대로 **파일로 저장된 SQL** 만 경로로
기억한다 — 원본 파일이 진실이므로 사본을 두지 않는다. 그래서 지운 파일을 되살리지는
못하고(그건 초안 캐시의 일이다), 파일이 사라졌으면 열려고 할 때 목록에서 빠진다.

목록은 최대 30개까지 남고, 항목의 `×` 를 누르면 **파일은 그대로 두고** 목록에서만 뺀다.

## 객체 상세 정보

트리에서 테이블·뷰·시퀀스·함수·프로시저를 **더블클릭**하면 상세 화면이 열린다.
(컬럼을 더블클릭하면 그 컬럼이 속한 테이블이 열린다. 한 번 클릭은 펼치기만 하고
아무 조회도 하지 않는다 — 트리를 훑는 것만으로 서버에 부담을 주지 않기 위해서다.
목록 열기 방식을 이미 더블클릭으로 설정했다면 그 설정을 따른다.)

| 구획 | 내용 |
| --- | --- |
| 속성 | MySQL: 엔진·크기·콜레이션 · PostgreSQL: 소유자·전체 크기·테이블스페이스 · Oracle: 테이블스페이스·상태·최근 DDL |
| 컬럼 | 이름 · 타입 · NULL 허용 · 기본값 · 설명, 기본 키에 🔑 |
| 인덱스 | 이름 · 고유 여부 · 컬럼 순서 (식 인덱스 포함) |
| 외래 키 | 나가는 참조와 **들어오는 참조**(이 테이블을 참조하는 쪽) · ON DELETE |
| 정의 | `SHOW CREATE` / `pg_get_viewdef` · `pg_get_functiondef` / `DBMS_METADATA.GET_DDL` |
| 시퀀스 | 현재값 · 증가치 · 최소/최대 · 순환 여부 |

화면 위의 버튼으로 **데이터 보기**(상위 200건), **SELECT 생성**(컬럼을 나열한 SELECT 문),
**DDL 열기**(정의를 새 편집기로), **새로고침** 을 할 수 있다.

외래 키의 상대 테이블 이름을 누르면 그 테이블의 상세로 이동한다. 들어오는 참조는
"이 행을 지우면 무엇이 깨지나"를 보여주므로 기본으로 접어 두되 목록에는 항상 포함한다.

서버가 DDL 을 주지 않는 경우(PostgreSQL 테이블, 권한이 없는 Oracle)에는 컬럼·기본 키·
인덱스 메타데이터로 **근사 DDL** 을 조립해 보여주고, 근사임을 화면에 명시한다.
제약 조건·파티션·스토리지 옵션은 담기지 않는다.

조각(컬럼 · 인덱스 · 속성 · DDL)은 따로 실패할 수 있다. 권한이 없어 DDL 을 못 읽어도
나머지는 그대로 보이고, 실패한 조각만 안내 문구로 남는다 — 하나 실패했다고
화면 전체가 오류가 되면 도구로 쓸 수 없다.

패널은 하나만 두고 내용을 갈아 끼운다. 스키마를 훑는 동안 편집기가 탭으로 뒤덮이지 않게.

## 자동 완성

단순 키워드 나열이 아니라 커서 위치의 문맥을 본다.

```sql
SELECT u.|                      -- users 의 컬럼 (별칭 u 를 추적)
  FROM users u
  JOIN orders o ON u.id = o.|   -- orders 의 컬럼
```

- `별칭.` → 그 테이블의 컬럼 (타입 · PK · 코멘트를 함께 표시)
- `스키마.` → 그 스키마의 테이블과 객체
- `시퀀스.` → Oracle 의 NEXTVAL / CURRVAL
- `FROM` / `JOIN` 뒤 → 테이블과 스키마 (기본 스키마를 위로 정렬)
- 그 외 → 현재 문장이 참조하는 테이블의 컬럼 우선, 그다음 함수 · 키워드

문자열 리터럴과 주석 안에서는 제안하지 않는다.

**연결이 닫혀 있어도 제안한다.** 스키마 캐시는 연결이 끊겨도 남아 있으므로, 창을 다시
켠 직후처럼 세션이 없을 때는 마지막으로 읽어 둔 스냅샷으로 제안한다. 캐시조차 없으면
목록 맨 위에 **"…에 연결"** 항목이 떠서 이유를 알려 주고, 고르면 그 자리에서 연결한다
(글자는 바뀌지 않는다). 편집기에 연결을 지정해 뒀다면 그 연결의 스키마만 본다 —
다른 DB 의 테이블 이름이 섞이면 없는 이름을 자신 있게 제안하는 꼴이 된다.

### 분류 순환

같은 자리에서 `Ctrl+Space` 를 다시 누르면 한 분류씩 넘어간다.

```
1회   문맥 추천        지금 위치에서 가장 그럴듯한 것들
2회   테이블
3회   뷰
4회   시퀀스
5회   함수 · 프로시저
6회~  패키지 · 동의어 · 타입   (연결에 실제로 있는 것만)
끝    컬럼 → 키워드 → 다시 1회로
```

각 항목 옆에 `시퀀스 4/8` 처럼 현재 분류와 위치가 표시된다.
해당 연결에 존재하는 분류만 순환에 들어가므로, 시퀀스가 없는 MySQL 연결에서
빈 목록을 거치지 않는다. 한 글자라도 입력하면 순환은 처음으로 돌아간다.

시퀀스는 이름만 넣어서는 쓸 수 없어 방언에 맞는 형태로 삽입된다 —
PostgreSQL 은 `nextval('seq')`, Oracle 은 `seq.NEXTVAL`, MariaDB 는 `NEXTVAL(seq)`.

메타데이터는 연결당 캐시하며(`dbconn.metadata.cacheTtlMs`), 만료돼도 이전 값을
즉시 돌려주고 백그라운드에서 갱신한다 — 팝업이 네트워크를 기다리며 멈추지 않는다.

## 결과 패널

**편집기 하나가 결과 탭 묶음 하나를 갖는다.** 같은 문서에서 다시 실행하면
이전 결과를 대체하므로, 같은 쿼리를 반복해도 탭이 쌓이지 않는다.
남겨서 비교하고 싶은 결과는 탭의 압정(📍)을 눌러 고정하면 대체되지 않는다.

`Ctrl+Shift+Enter` 로 여러 구문을 실행하면 구문마다 탭이 생기지만,
그 묶음 전체가 다음 실행 때 함께 교체된다.

### 선택 · 정렬 · 복사

결과 그리드는 표 도구처럼 **셀 블록**을 다룬다. 브라우저의 글자 선택이 아니라
행·열 좌표를 가진 블록이므로, 복사한 내용이 구조를 그대로 유지한다.

| 조작 | 동작 |
| --- | --- |
| 행 번호 클릭 | 그 행 전체를 블록으로 선택 (`Shift` 로 범위, `Ctrl` 로 추가) |
| 셀 클릭 · 드래그 | 사각형 블록 선택 (`Shift`+클릭/방향키로 확장) |
| `Ctrl+A` | **조회 결과 행만** 전체 선택 (탭·툴바 글자는 잡히지 않는다) |
| `Ctrl+C` | 선택 블록을 TSV 로 복사 — 행은 줄바꿈, 열은 탭 |
| `Ctrl+Shift+C` | 컬럼 이름을 붙여서 복사 |
| 컬럼 헤더 클릭 | 정렬: 오름차순 → 내림차순 → 해제 |
| 컬럼 경계 드래그 | 너비 조절 (더블클릭하면 내용에 맞춤) |
| `Alt+Enter` 또는 읽기 전용 셀 더블클릭 | 셀 값 전체 보기 (JSON 펼치기 · 복사) |
| 좌상단 모서리 클릭 | 전체 선택 |

컬럼 너비는 헤더 경계에 커서를 대면 나타나는 손잡이를 끌어 조절한다.
조절한 너비는 탭에 남아 결과를 다시 그려도 유지되고, 손잡이를 더블클릭하면
내용 길이에 맞춘 기본값으로 돌아간다.

정렬은 화면 순서만 바꾸고 원본 행 번호를 그대로 추적하므로, 정렬된 상태에서
셀을 고쳐도 올바른 행에 UPDATE 가 나간다. NULL 은 방향과 무관하게 항상 끝에 모으고,
드라이버가 문자열로 주는 숫자(BIGINT·DECIMAL)도 수치로 비교한다.

한 줄로 잘려 보이는 긴 값(JSON · 로그 · 본문)은 **셀 값 뷰어**로 통째로 본다.
JSON 으로 읽히면 들여쓴 형태로 펼칠 수 있고, 서버 값이 잘려 온 경우에는 그 사실을 함께 알린다.

복사한 TSV 는 스프레드시트·에디터에 그대로 붙여 넣으면 블록 모양이 유지된다.
값 안의 탭·줄바꿈은 공백으로 바뀐다 — 그러지 않으면 한 셀이 여러 줄로 쪼개져 표가 어긋난다.

### 페이징 · 이어 조회 · 서버 정렬

`maxRows`(기본 1000)를 넘는 결과는 잘리는 대신 **쪽 단위로 넘겨 본다.**
툴바의 `◀` `▶` 와 현재 구간(`1–1,000행 · 이후 더 있음`)이 그 역할을 한다.

**맨 아래까지 스크롤하면 다음 묶음을 기존 결과 뒤에 이어 붙인다.** 쪽을 넘기는 것과
달리 화면이 갈리지 않으므로, 보고 있던 위치와 선택이 그대로 유지된 채 목록만 길어진다.

- 자동 이어 조회는 `dbconn.execution.maxLoadedRows`(기본 50,000행)에서 멈춘다.
  수십만 행을 스크롤만으로 쌓으면 확장이 아니라 편집기 창이 먼저 죽는다.
  멈춘 뒤에도 툴바의 **더 불러오기** 를 누르면 계속 가져온다(이쪽은 한도를 보지 않는다).
- `dbconn.execution.autoLoadMore` 를 끄면 스크롤로는 부르지 않고 단추로만 가져온다.
- 이어 붙이는 중에 다른 쪽으로 옮겨 가면 도착한 묶음은 버려진다 — 다른 구간의 행이
  섞이지 않게.

**행 제한은 툴바에서 바로 바꾼다.** 선택 상자(100 ~ 50,000 · 직접 입력)에서 고르면
`dbconn.execution.maxRows` 에 저장되고, 보고 있던 결과도 새 크기로 다시 읽는다.
명령 팔레트의 **DBConn: 결과 행 제한 변경** 과 결과 패널 제목 단추도 같은 일을 한다 —
큰 테이블을 건드리기 **전에** 제한부터 낮추는 것이 이 설정을 만지는 가장 흔한 이유다.

- 첫 쪽은 사용자가 쓴 SQL 을 그대로 돌린 결과다. 다음 쪽부터 원본을 파생 테이블로 감싸
  `LIMIT/OFFSET`(Oracle 은 `OFFSET … FETCH NEXT`)을 건다. 원본 문장에 절을 끼워 넣지 않으므로
  사용자가 쓴 SQL 의 구조가 바뀌지 않는다.
- 다음 쪽이 있는지는 **한 행을 더 요청해서** 판단한다. `COUNT(*)` 로 총 건수를 세지 않는다 —
  큰 테이블에서 그 한 번이 페이지 이동 전체보다 비싸다.
- 감싸면 의미가 달라지는 구문(`SELECT … INTO`, `FOR UPDATE`, 이름이 중복된 컬럼)은
  페이징을 켜지 않는다.
- 원본 쿼리에 `ORDER BY` 가 없으면 쪽 사이의 행 순서는 서버가 보장하지 않는다.
  순서가 중요하면 `ORDER BY` 를 쓰거나 헤더를 눌러 정렬한다.

**정렬은 두 가지로 갈린다.** 결과가 화면에 전부 있으면 클라이언트에서 즉시 정렬하고,
잘렸거나 다른 쪽을 보고 있으면 **서버에 다시 물어 전체를 정렬한다**(첫 쪽으로 돌아간다).
가져온 1000행 안에서만 정렬해 놓고 "전체가 정렬됐다"고 보이게 하지 않기 위해서다.
서버 정렬은 컬럼 위치(`ORDER BY 3`)로 걸어, 함수 결과처럼 이름이 이상한 컬럼에서도 어긋나지 않는다.

### 그리드에서 직접 수정 · 삭제

조회 결과가 **단일 테이블이고 기본 키가 결과에 포함**되면 그리드에서 바로 고칠 수 있다.
편집 가능한 결과는 툴바에 `스키마.테이블 편집 가능` 이 표시되고,
기본 키 컬럼 헤더에 🔑 가 붙는다.

| 조작 | 동작 |
| --- | --- |
| 셀 더블클릭 · `Enter` · `F2` | 인라인 편집 (`Enter` 확정 / `Esc` 취소) |
| `Ctrl+Delete` | 선택한 셀을 NULL 로 |
| 툴바 **행 추가** | 그리드 아래 초안 행에 값을 채워 INSERT |
| 툴바 **행 삭제** | 선택한 행 DELETE |

**행 추가**는 값을 채운 칸만 구문에 넣는다. 빈 칸은 생략되어 서버의 기본값·시퀀스가 채운다 —
빈 칸을 NULL 로 밀어 넣으면 NOT NULL 컬럼이 있는 테이블에는 아무 행도 넣을 수 없기 때문이다.
추가 후에는 현재 쪽을 다시 읽어, 서버가 채운 값까지 그대로 보여준다.

편집이 열리는 조건은 의도적으로 좁다. 하나라도 어긋나면 읽기 전용으로 남는다:

- 조인 · 집계 · `GROUP BY` · `DISTINCT` · 집합 연산 · 서브쿼리 · CTE · 윈도 함수가 없을 것
- 대상이 테이블일 것 (뷰는 갱신 가능 여부를 알 수 없어 제외)
- 기본 키가 있고, 그 컬럼이 결과에 **모두** 포함될 것
- 이름이 중복된 컬럼은 편집 대상에서 제외 (어느 쪽인지 모호하므로)

셀 단위로는 **가공되지 않은 원본 컬럼**만 열린다. SELECT 목록을 읽어
`name AS nm` 처럼 이름만 바뀐 값과 `UPPER(name) AS name` 처럼 함수를 거친 값을
구분한다 — 앞은 편집 가능(UPDATE 는 실제 컬럼 이름으로 나간다), 뒤는 읽기 전용이다.
이름만 보고 맞추면 화면에 없는 원본 값을 덮어쓰는 UPDATE 가 만들어진다.
같은 컬럼을 두 번 뽑은 경우도 기준 셀이 모호해 제외된다.

편집 가능 판정에는 스키마 메타데이터가 필요하다. 연결 직후처럼 캐시가 아직
없으면 결과를 먼저 보여 준 뒤, 카탈로그가 도착하는 대로 다시 판정해 그리드를
편집 가능으로 바꾼다.

실행될 SQL 은 적용 전에 그대로 보여주고 확인받는다
(`dbconn.edit.confirmEachChange` 로 끌 수 있다). WHERE 는 기본 키 전체로
구성되므로 최대 1행에만 닿고, 영향 행 수가 1이 아니면 실패로 처리해 알린다 —
0행이면 다른 곳에서 이미 바뀐 것이므로 조용히 넘어가서는 안 된다.

값은 어떤 경우에도 바인드 파라미터로 나간다. 문자열 조립에 값이 끼는 경로는 없다.

## 운영 DB 안전장치

연결마다 **환경**(개발 · 스테이징 · 운영)을 지정한다. 읽기 전용과는 별개다 —
운영이지만 쓰기가 필요한 연결이 실제로 흔하기 때문이다.

### 눈에 보이는 경고

| 위치 | 운영 | 스테이징 |
| --- | --- | --- |
| 트리 아이콘 | 오른쪽 아래 빨간 점 + `운영` 꼬리표 | 노란 점 + `스테이징` 꼬리표 |
| 상태바 | 배경 전체가 오류색 + `[운영]` | 배경이 경고색 + `[스테이징]` |
| 결과 패널 | 연결 이름 앞 빨간 배지 | 노란 배지 |
| 폴더 | 접혀 있어도 `운영 포함` 으로 표시 | — |

사고의 대부분은 "운영에 붙어 있는 줄 모르고" 일어난다. 그래서 환경 표시는
프로필의 부가 정보가 아니라 화면 어디서나 같은 색과 같은 말로 나타난다.

### 확인 강화

운영 연결에서 데이터·스키마를 바꾸는 구문을 실행하면, 위험도와 **무관하게** 확인을 받는다
(`dbconn.execution.productionGuard`, 기본 `type-to-confirm`):

1. 무엇이 실행되는지 보여주는 경고 대화상자
2. **대상 이름을 직접 입력** — `DROP TABLE public.users` 면 `users` 를 타이핑해야 실행된다

손이 기억한 대로 Enter 를 누르는 것을 막는 것이 목적이다. 대상 이름은 구문에서 뽑고
(`UPDATE x` · `DELETE FROM x` · `ALTER TABLE x` · `TRUNCATE x` …), 알 수 없으면 연결 이름을 쓴다.
`confirm` 으로 낮추면 1단계만, `off` 면 일반 위험 구문 확인만 적용된다.

그리드 편집(UPDATE/DELETE)은 **운영에서 `dbconn.edit.confirmEachChange` 설정과 무관하게 항상 확인한다.**
확인을 꺼 둔 채 운영에 붙는 것이 가장 흔한 사고 경로다.

### 연결 테스트

저장하기 전에 실제로 접속해 볼 수 있다. 연결 화면 아래의 **연결 테스트** 는
몇 번이든 반복할 수 있고, 트리에서 연결을 우클릭해 **연결 테스트** 로도 확인한다.

풀을 쓰지 않고 커넥션 하나를 직접 열었다가 닫으므로 세션이나 풀 상태에 흔적을 남기지 않는다.
비밀번호를 저장하지 않는 프로필은 이번 테스트에만 쓸 값을 물어본다.

### 연결 화면이 뜨는 곳

VShoon에 포함된 DBConn의 연결 추가/편집 화면은 Workbench 위의 **모달 편집기**로 뜬다.
기존 SQL 편집기와 창 배치는 그대로 유지되며, 모달 바깥은 입력을 받지 않는다. `Esc`,
바깥 영역 클릭 또는 닫기 버튼으로 취소할 수 있고 키보드 포커스는 모달 안에 머문다.

같은 소스를 일반 VS Code 확장으로 실행하면 VShoon 전용 capability가 없으므로 안전하게
일반 웹뷰 편집기 탭으로 열린다.

## 연결 목록 · 폴더

### 아이콘

연결 아이콘 하나가 세 가지를 동시에 말한다.

| 신호 | 표현 |
| --- | --- |
| 어떤 DB 인가 | 제품 로고 — MySQL 돌고래, MariaDB 물개, PostgreSQL 코끼리, Oracle 마크 |
| 연결돼 있는가 | 색이 살아 있으면 연결됨, 회색이면 끊김 |
| 어떤 환경인가 | 오른쪽 아래 점 — 운영은 빨강, 스테이징은 노랑, 개발은 점 없음 |

로고 뒤에 **배경(판)을 깔지 않는다.** 트리의 다른 항목은 모두 배경 없는 글리프라,
판을 깐 연결만 스티커처럼 도드라진다. 대신 로고가 상자를 꽉 채우게 해서 16px 에서도
형태로 구분되게 하고, 환경 점이 놓일 자리는 로고에서 **도려낸다** — 흰 테두리를 두르면
밝은 테마에서 얼룩으로 남지만, 도려낸 자리는 테마의 배경색이 그대로 보인다.
Oracle 원본은 128 높이 한가운데 놓인 가로 워드마크라 16px 로 줄이면 붉은 실선이 되므로,
앞쪽 `O` 만 잘라 상자를 채운다.

같은 아이콘을 **활성 연결 선택** 목록에서도 쓴다 — 목록에서 고른 것과 트리에 있는 것이
달라 보이면 어느 연결인지 다시 확인하게 된다.

파일은 `npm run icons` 로 만든다. 방언 × 연결 상태 × 환경 = 24개라
손으로 두면 반드시 어긋나고, 빠져도 오류 없이 빈 칸만 남아서 테스트가 파일 존재를 대조한다.

> **상표 고지** — MySQL 은 Oracle Corporation, MariaDB 는 MariaDB Corporation Ab,
> PostgreSQL 은 PostgreSQL Community Association, Oracle 은 Oracle Corporation 의 상표다.
> 이 확장은 각 제품과 제휴 관계가 없으며, 로고는 연결이 **어떤 제품을 가리키는지 표시하는
> 용도로만** 쓴다. 로고 SVG 는 [Devicon](https://devicon.dev)(MIT)에서 가져와 합성했다.

### 폴더

연결이 늘어나면 사이드바에서 폴더로 묶을 수 있다 (`운영/서울` 처럼 계층도 가능,
최대 8단계).

| 조작 | 동작 |
| --- | --- |
| 뷰 제목의 **폴더 추가** | 최상위 폴더 생성 |
| 폴더 우클릭 → **하위 폴더 추가** · **이름 변경** · **삭제** | 폴더 관리 |
| 연결 우클릭 → **폴더로 이동** | 목록에서 폴더 선택(또는 새로 만들기) |
| `F2` | 선택한 **연결 또는 폴더의 이름 변경** (우클릭 메뉴에도 있다) |
| `Ctrl+C` · `Ctrl+V` | 연결 **복사 · 붙여넣기** (여러 개 골라 한 번에도 된다) |
| 연결 **더블클릭** | 접속. 한 번 클릭은 고르기일 뿐이다 |
| 끌어다 놓기 | 연결·폴더를 폴더 안으로, 또는 빈 곳에 놓아 최상위로 |

### 연결 복사

비슷한 연결을 여럿 만들 때 `Ctrl+C` → `Ctrl+V`. 붙여 넣은 자리가 곧 목적지다 —
폴더 위에서 누르면 그 폴더로, 연결 위에서 누르면 그 연결 옆에 생긴다.

- 이름에는 `(복사본)` 이 붙고, 이미 있으면 `(복사본 2)`, `(복사본 3)` 으로 이어진다.
  복사본을 다시 복사해도 꼬리가 자라지 않는다.
- **비밀번호도 함께 복사된다.** 다만 화면이나 클립보드를 거치지 않고 OS 자격 증명
  저장소 안에서만 옮긴다 — 복제본이 곧바로 접속되지 않으면 복사할 이유가 없고,
  그렇다고 비밀번호를 밖으로 꺼낼 이유도 없다.
- 연결을 복사해도 **시스템 클립보드는 건드리지 않는다.** 프로필에는 내부 호스트명과
  계정이 들어 있어서, 다른 곳에 무심코 붙여 넣으면 그대로 새어 나간다.
  이름만 클립보드로 보내려면 우클릭 → **이름 복사**.
- 복사한 뒤 원본을 고치거나 지워도 붙여 넣을 수 있다(스냅샷을 들고 있다).
  단 원본을 지웠다면 저장된 비밀번호는 함께 사라진다.

접속은 **더블클릭에서만** 일어난다. 목록을 훑는 것만으로 세션이 열리면
운영 DB 에서 특히 위험하기 때문이다(테이블 상세를 여는 규칙과 같고,
`workbench.list.openMode` 를 더블클릭으로 두었다면 그 설정을 따른다).

연결 이름은 표시용이라 `F2` 로 바꿔도 **연결이 끊기지 않는다.** 접속에 쓰이는 값
(호스트·포트·계정)을 고치는 **연결 편집** 은 풀 설정이 어긋나지 않게 세션을 다시 맺는다.

폴더 이름을 바꾸거나 옮기면 하위 폴더와 그 안의 연결이 함께 따라간다.
폴더를 지워도 **연결은 지워지지 않는다** — 상위 폴더(없으면 최상위)로 올라온다.
폴더는 별도 엔티티가 아니라 프로필에 붙은 경로라서, 트리와 저장소가 어긋날 수 없다.
비어 있는 폴더만 따로 기억해 새로고침 후에도 남는다.

## 커넥션 관리

좀비 커넥션과 풀 누수를 구조적으로 막는 것이 이 확장의 설계 중심이다.

**1. 반납이 강제된다.**
일반 쿼리는 전부 `withConnection()` 을 거치고 반납은 `finally` 에서 일어난다.
원시 대여는 트랜잭션 세션에만 열려 있다.

**2. 열린 트랜잭션은 풀로 돌아가지 않는다.**
반납 시점에 트랜잭션이 열려 있으면 무조건 롤백한다. 롤백이 실패하면 그
커넥션은 재사용하지 않고 폐기한다. 다음 사용자가 오염된 세션을 받는 경로가 없다.

**3. 자니터가 좀비를 회수한다.**
10초마다 대여 목록을 훑는다.

- `pool.leaseTimeoutMs`(기본 2분)를 넘긴 일반 대여 → 좀비로 간주, 강제 회수 후 폐기
- `pool.transactionIdleTimeoutMs`(기본 5분) 동안 유휴한 트랜잭션 → **자동 롤백** 후 반환

회수될 때는 알림이 뜨고, 로그에는 대여 시점의 스택이 남아 누수 지점을 특정할 수 있다.

**4. 종료 시 정리한다.**
`deactivate` 는 모든 풀이 닫힐 때까지 기다린다. 커밋되지 않은 트랜잭션은
롤백된다 — 창을 닫는 것이 커밋이 되어서는 안 되기 때문이다.

**5. 취소가 서버까지 간다.**
`Ctrl+Escape` 는 클라이언트에서 포기하는 데 그치지 않고 서버 측 실행을 중단시킨다.
MySQL 은 `KILL QUERY`, PostgreSQL 은 `pg_cancel_backend()`, Oracle 은 `break()`.

풀 상태는 **커넥션 풀 진단** 명령으로 언제든 확인할 수 있다.

## 다른 확장에서 연결 정보 읽기

`activate()` 가 읽기 전용 API 를 돌려준다. 확장이 아직 켜지지 않았을 수
있으니 `activate()` 를 반드시 `await` 한다.

```ts
import * as vscode from 'vscode';

const ext = vscode.extensions.getExtension<DbconnApi>('vshoon.vshoon-dbconn');
const api = await ext?.activate();

for (const profile of api?.getProfiles() ?? []) {
  console.log(profile.name, api?.getConnectionUrl(profile.id), profile.connected);
}

api?.onDidChangeProfiles(() => refreshMyView());
```

타입은 이 인터페이스를 복사해 쓰면 된다 (`src/api.ts` 가 원본).

```ts
interface DbconnApi {
  readonly version: 1;
  getProfiles(): DbconnProfileInfo[];
  getProfile(id: string): DbconnProfileInfo | undefined;
  /** 비밀번호가 없는 표시용 URL. */
  getConnectionUrl(id: string): string | undefined;
  readonly onDidChangeProfiles: vscode.Event<void>;
}

interface DbconnProfileInfo {
  readonly id: string;
  readonly name: string;
  readonly dialect: 'mysql' | 'mariadb' | 'postgres' | 'oracle';
  readonly host: string;
  readonly port: number;
  readonly database: string;
  readonly user: string;
  readonly environment: 'development' | 'staging' | 'production';
  readonly readOnly: boolean;
  readonly tlsEnabled: boolean;
  readonly folder: string | undefined;
  readonly connected: boolean;
}
```

일부러 뺀 것이 둘 있다.

- **비밀번호.** `SecretStorage` 밖으로 나가지 않는다. 다른 확장이 조용히
  자격 증명을 긁어 가는 경로를 만들지 않는다.
- **쓰기.** 프로필 추가·수정·삭제는 사용자가 이 확장의 UI 에서 한다.
  남의 확장이 목록을 바꿔 놓으면 사용자가 원인을 찾을 수 없다.

`getProfiles()` 가 주는 필드만 계약이다. 풀 옵션이나 인증서 경로처럼 내부
사정에 따라 바뀌는 필드는 담기지 않는다. 계약을 깨는 변경에는 `version` 이
올라간다.

| 비밀번호 | `SecretStorage`(OS 키체인)에만 저장. 프로필 객체·설정 파일·로그 어디에도 남지 않는다 |
| 연결 정보 | `globalState` 에 저장 — `settings.json` 에 두면 워크스페이스 커밋 시 내부 호스트명이 유출된다 |
| SQL 초안 캐시 | 확장의 전역 저장소(설정 동기화 대상 아님)에 평문으로 둔다. 쿼리에 자격 증명을 적는 습관이 있다면 `dbconn.scripts.cache` 를 끄는 편이 안전하다 |
| 실행 이력 | SQL 원문과 결과 요약만 남기고 결과 데이터는 저장하지 않는다. `dbconn.history.enabled` 로 끌 수 있다 |
| 실행 계획 측정 | 구문을 실제로 실행하므로 SELECT 에만 허용하고, 실행 전 확인을 받는다 |
| 운영 연결 | 환경 표시(색·배지)와 함께, 변경 구문 실행 전 대상 이름 입력을 요구한다 |
| 연결 테스트 | 비밀번호는 테스트 호출 동안에만 인자로 존재하고 저장되지 않는다 |
| SQL 인젝션 | 카탈로그 조회는 전부 바인드 파라미터. 식별자는 인용부호를 배가하는 `quoteIdentifier` 를 반드시 거친다 |
| 스택드 인젝션 | MySQL `multipleStatements: false` — 한 번의 호출로 여러 구문이 실행될 수 없다 |
| 웹뷰 XSS | CSP `default-src 'none'` + nonce. DB 값은 `postMessage` 로 보내 `textContent` 로만 넣는다 (`innerHTML` 미사용) |
| TLS | 기본 검증 켬. 끄려면 명시적 경고를 거쳐야 하고, 사설 CA 는 파일 경로로 지정 |
| 읽기 전용 | 서버 세션을 읽기 전용으로 설정 + 클라이언트에서 쓰기 구문 차단 (이중 방어) |
| 위험 구문 | `WHERE` 없는 `UPDATE`/`DELETE`, `DROP`/`TRUNCATE` 는 실행 전 모달 확인 |
| 공개 API | 다른 확장에는 연결 메타데이터만 읽기 전용으로 내보낸다. 비밀번호와 쓰기 경로는 API 에 없다 |
| 로그 | 비밀번호·접속 문자열 자격 증명을 정규식으로 마스킹 |
| 가져오기 | 다른 설치본의 저장소는 임시 복사본으로 읽기만 한다. 복호화한 비밀번호는 `SecretStorage` 로 바로 들어가고 화면·클립보드·로그를 거치지 않는다. 복호화는 같은 Windows 사용자 계정에서만 가능하다 |
| 메모리 | 셀 값 64KB, 고정하지 않은 결과 탭 12개로 제한. 대용량 조회는 서버 측 `LIMIT` 으로 자름 |
| 그리드 편집 | 단일 테이블 + 기본 키 완비일 때만 허용. 값은 바인드 파라미터, 적용 전 확인, 영향 행 수 검증 |

## 설정

주요 항목만 추렸다. 전체는 설정에서 `dbconn` 으로 검색.

| 키 | 기본값 | 설명 |
| --- | --- | --- |
| `dbconn.execution.maxRows` | 1000 | 한 번에 가져올 최대 행 수 (결과 툴바에서 바로 조절) |
| `dbconn.execution.autoLoadMore` | true | 맨 아래까지 스크롤하면 다음 묶음을 이어 조회 |
| `dbconn.execution.maxLoadedRows` | 50000 | 자동 이어 조회로 쌓아 둘 행 수 상한 |
| `dbconn.execution.queryTimeoutMs` | 60000 | 쿼리 타임아웃 |
| `dbconn.execution.confirmDestructive` | true | 위험 구문 확인 |
| `dbconn.execution.productionGuard` | type-to-confirm | 운영 연결의 변경 구문 확인 강도 |
| `dbconn.execution.autoCommit` | true | 자동 커밋 기본값 |
| `dbconn.pool.max` | 5 | 연결당 최대 커넥션 |
| `dbconn.pool.leaseTimeoutMs` | 120000 | 좀비 판정 기준 |
| `dbconn.pool.transactionIdleTimeoutMs` | 300000 | 트랜잭션 자동 롤백 기준 |
| `dbconn.completion.keywordCase` | upper | 키워드 대소문자 |
| `dbconn.metadata.cacheTtlMs` | 300000 | 스키마 캐시 유효 시간 |
| `dbconn.edit.enabled` | true | 결과 그리드 직접 편집 |
| `dbconn.edit.confirmEachChange` | true | 편집마다 SQL 확인 (운영에서는 항상 확인) |
| `dbconn.history.enabled` | true | 쿼리 실행 이력 기록 |
| `dbconn.scripts.newQueryLocation` | folder | 새 SQL 편집기를 파일로 만들지, 이름 없는 문서로 열지 |
| `dbconn.scripts.folder` | (비움) | 쿼리 보관 폴더 (비우면 `~/.vscode/dbconn/queries`) |
| `dbconn.scripts.autoSave` | true | 보관 폴더 안 SQL 파일 자동 저장 |
| `dbconn.scripts.cache` | true | 저장하지 않은 SQL 초안 캐시 |
| `dbconn.scripts.restore` | prompt | 시작 시 초안 복구 방식 |

## 개발

```bash
npm install
npm run watch     # esbuild 감시 모드
npm run check     # 타입 검사
npm test          # 단위 테스트
npm run build     # 배포 번들
```

VS Code 에서 `F5` 를 누르면 확장 개발 호스트가 뜬다.

### 구조

```
src/
├── sql/          방언 중립 SQL 처리
│   ├── tokenizer.ts  문자열·주석·$·백틱을 아는 렉서
│   ├── statements.ts 문장 분리 (Ctrl+Enter 의 근거)
│   ├── context.ts    커서 문맥 + 별칭 추적 (자동 완성의 근거)
│   ├── guard.ts      구문 분류 · 위험도 · 읽기 전용 차단
│   ├── paging.ts     쪽 단위 조회 · 서버 정렬 SQL 조립
│   └── editable.ts   그리드 편집 가능 여부 판정
├── db/           드라이버 추상화와 커넥션 풀
│   ├── driver.ts        RawConnection / Driver 인터페이스 (경계)
│   ├── pool.ts          대여 추적 + 자니터
│   ├── session.ts       트랜잭션 상태 기계
│   ├── rowEditor.ts     편집 → 파라미터화된 UPDATE/DELETE
│   ├── catalogDetail.ts 상세 조회 결과 정리 + 근사 DDL
│   ├── connectionTest.ts 저장 전 실제 접속 확인
│   └── {mysql,postgres,oracle}/
├── metadata/     스키마 캐시 + 객체 상세 수집
├── features/     자동 완성(+분류 순환), 실행·계획, 행 편집, 초안 캐시, 실행 이력, 명령
├── views/        트리, 결과 패널, 객체 상세 패널, 상태바, 연결 폼(웹뷰)
├── config/       프로필 저장소 (SecretStorage) + 연결 폴더 경로 + 환경 표시 규칙
└── api.ts        다른 확장에 공개하는 읽기 전용 API (비밀번호·쓰기 제외)
```

각 DB 라이브러리의 타입은 `db/{dialect}/driver.ts` 안에서만 존재하고
`RawConnection` 경계를 넘지 않는다. 새 방언을 추가하려면 그 인터페이스를
구현하고 `db/registry.ts` 에 등록하면 된다.

### 테스트

부작용이 없는 핵심 로직을 242개 케이스로 덮는다 — 문장 분리, 구문 분류,
식별자 인용, 문맥 분석, 행 제한, 페이징 SQL, 편집 가능 판정, 편집 SQL 생성,
확인 대상 객체 추출, 환경 표시 규칙, 폴더 경로 조작, 상세 정보 정리와
근사 DDL(외래 키 포함), 초안 캐시와 실행 이력 색인.
버그가 조용히 데이터를 망가뜨리는 영역이라 우선순위를 뒀다.

특히 편집 관련 테스트는 "거부해야 하는 경우"에 무게를 뒀다. 조인·집계·
서브쿼리·뷰·PK 누락 중 하나라도 새면 엉뚱한 행을 고치는 UPDATE 가 만들어진다.

#### 드라이버 통합 테스트

방언별 SQL(카탈로그 조회 · 외래 키 · 실행 계획 · 페이징 래퍼 · 편집 구문)은
문법이 조금만 어긋나도 실패하는데, 순수 로직 테스트로는 잡을 수 없다.
그래서 실제 서버에 던져 보는 층을 따로 둔다.

```bash
npm run it:up                  # MySQL · MariaDB · PostgreSQL · Oracle
npm run test:integration
```

- 필요한 것만 띄워도 된다. **접속되지 않는 대상은 실패가 아니라 건너뛴다** —
  Postgres 만 띄우고 작업하는 것이 정상이고, 그때 Oracle 때문에 빨간불이 뜨면 아무도 돌리지 않는다.
- 스키마는 매 실행마다 지우고 다시 만든다 (`test/integration/seed.ts`).
- 확장 호스트 밖에서 드라이버를 돌리기 위해 `vscode` 모듈을 최소 대역으로 갈아 끼운다
  (`test/integration/bootstrap.cjs`). 대역에 없는 API 를 드라이버가 쓰기 시작하면 즉시 오류로 드러난다.
- 접속 정보는 `DBCONN_IT_<방언>_HOST/PORT/USER/PASSWORD/DATABASE` 로 덮어쓸 수 있고,
  `DBCONN_IT_SKIP=oracle,mariadb` 로 특정 방언을 건너뛴다.

GitHub Actions 는 PostgreSQL · MySQL 서비스 컨테이너로 이 테스트를 돌린다
(Oracle 은 이미지가 커서 로컬 확인용).

## 알려진 제한

- Oracle 은 thin 모드로만 접속한다. 서버 12.1 이상이 필요하고,
  11g 이하는 `ORA-28040` 로 거부된다.
- 그리드 편집은 단일 테이블 + 기본 키 완비 조회에서만 열린다.
  조인 결과나 뷰를 고치려면 SQL 을 직접 쓰면 된다.
- 기본 키 자체는 편집 대상에서 제외된다 (WHERE 의 기준이 바뀌므로).
- 대용량 결과는 스트리밍이 아니라 쪽 단위로 가져온다. 총 건수는 세지 않으므로
  "몇 쪽 중 몇 쪽"은 표시하지 않고, 다음 쪽 유무만 보여준다.
- 페이징·서버 정렬은 원본 SQL 을 파생 테이블로 감싼다. 이름이 중복된 컬럼이나
  `FOR UPDATE` 처럼 감쌀 수 없는 구문에서는 켜지지 않는다.
- MySQL `DELIMITER` 는 구문 분리 목적으로만 해석한다.
